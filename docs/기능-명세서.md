# Mirror-Ting 기능 명세서

기준일: 2026-09-28  
대상: 전시용 화면 `mvp/`, 분석 서버 `poc/backend/`  
이 문서는 현재 구현된 기능을 기준으로 한다. 기획 초안과 구현이 다르면 코드를 따른다.

## 1. 제품 개요

Mirror-Ting은 취업 준비생이 가상 직장 대화를 역할극으로 연습하고, 응답·목소리·표정·자세를 4-Fit으로 받아 보는 시스템이다. 2026 동양미래EXPO 졸업작품(동아리 CarpeDM)의 전시 화면이 1차 사용자 접점이다.

사용자는 직무·상황·난이도를 고른 뒤 AI 상대와 대화한다. 브라우저는 카메라·마이크로 비언어 지표를 집계하고, 서버는 대화를 이어 가며 세션이 끝나면 리포트를 만든다. 영상 원본은 서버로 보내지 않는다.

## 2. 사용자와 범위

| 사용자 | 하는 일 | 화면 |
| --- | --- | --- |
| 전시 관람객 | 모드 선택, 역할극, 결과 확인 | `mvp/` (포트 5173) |
| 운영자 | 지표 확인, CSV 내보내기, 초기화 | 백엔드 `/api/admin`. 레거시 웹앱 `poc/frontend/`의 관리 화면 |
| 기관(B2B) | 초대 코드로 합류, 수강 세션 조회, NFC 카드 발급 | 기관·NFC API. 전시 기본 동선과는 분리 |

레거시 웹앱(`poc/frontend/`, 포트 5174)은 기능을 유지하지만 전시 당일 화면은 `mvp/`다.

## 3. 전시 화면 흐름

`mvp/src/lib/serviceEntryRoute.js`의 순서다.

1. 사용방법
2. 사이트 소개
3. 결과 및 기록
4. 서비스 모드 선택
5. 메인
6. 직무 선택
7. 시나리오 선택
8. 난이도 선택
9. 시나리오 미리보기 (동의, 카메라·마이크 권한)
10. AI와 연습하기
11. 결과 보고서

직접 시연용 쿼리: `?demo=practice`, `?demo=records`, `?demo=result`. NFC 발급 키오스크는 `?kiosk=issue`.

홈에서 오래 방치하면 안내 루프로 돌아가고, 결과 화면은 기본 90초 무조작 시 복귀한다. `?idle=0`이면 결과 화면 자동 복귀를 끈다. 시연 촬영 중에는 세션이 지워지지 않도록 이 값을 쓴다.

### 3.1 서비스 모드

| ID | 이름 | 연습 내용 |
| --- | --- | --- |
| `interview` | 면접 | 자기소개와 직무 질문에 답하는 모의면접 |
| `training` | 직업훈련 | 고객 응대와 현장 업무 대화 |
| `workplace` | 직장대화 | 보고, 피드백, 협업. 팩에 직장 카테고리가 없으면 훈련 모드로 내려간다 |

### 3.2 직무와 난이도

직무 선택: 개발자(`office_admin`), 카페 파트너(`cafe_crew`), 상담사(`cs_agent`).

| ID | 이름 | 상대 태도 |
| --- | --- | --- |
| `basic` | 기본 모드 | 차분한 질문, 여유 있는 답변 |
| `pressure` | 진상 모드 | 불만, 추가 질문, 대안 요구 |
| `ultra_pressure` | 왕진상 모드 | 연속 질문, 빠른 판단 |

직장대화 전용 시나리오(`workplace-conversation`)는 면접·직업훈련 목록에 넣지 않는다.

## 4. 역할극

세션 상태: `ready` → `in_progress` → `analyzing` → `completed`. 중단은 `aborted`.

한 턴의 처리:

1. 상대 대사를 보여 주고, 설정이 있으면 서버 TTS로 읽는다. TTS가 없으면 브라우저 음성 합성을 쓴다.
2. 사용자는 말한다. 실시간 받아쓰기는 Chrome 음성 인식이다. 실패하면 직접 입력으로 넘긴다.
3. 브라우저는 그 구간의 표정·자세·시선 집계를 서버에 보낸다.
4. 같은 턴의 녹음(WAV)을 올린다. 업로드 제한은 30초다.
5. 서버가 답변을 받아 다음 상대 대사를 만든다.
6. 사용자가 종료하면 분석이 비동기로 돌고, 진행률을 폴링한 뒤 리포트를 연다. 실패하면 분석 재시도를 할 수 있다.

저장된 세션은 상태에 따라 이어 한다. 진행 중이면 연습 화면, 분석 중이거나 완료면 결과 화면이다.

대화 생성은 서버 설정 `MIRROR_TING_DIALOGUE_PROVIDER`가 고른다. 기본값은 `gemini`이고 `openai`를 쓸 수 있다. 호출이 실패하거나 형식이 맞지 않으면 직장대화는 시나리오 팩의 BeatSheet 문장으로 넘어간다. API 키는 서버 `.env`에만 둔다.

## 5. 4-Fit 분석

점수 엔진 버전은 `4`다. 원시 지표는 `band_score`로 0~100이 된 뒤 가중 평균한다. 측정되지 않은 축은 빼고, 남은 축의 가중치로 다시 나눈다. 버전이 다른 세션의 점수 추이는 섞지 않는다.

| 축 | 가중치 (잠정) | 측정 |
| --- | --- | --- |
| Response-Fit | 0.35 | 답변이 상황·목표에 맞는지. 로컬 E5 의미 매칭. 모델 파일이 없으면 키워드 판정 |
| Voice-Fit | 0.30 | 녹음이 있으면 음성 특징 실측. 음성 인식 턴은 발화 시간 근사. 텍스트만 입력한 턴은 측정에서 뺀다 |
| Expression-Fit | 0.175 | 브라우저 MediaPipe 표정 지표를 서버가 점수화. 개인 무표정 대비. 참고 지표에 가깝다 |
| Posture-Fit | 0.175 | 브라우저가 보낸 자세 지표를 서버가 점수화 |

가중치는 검증 전 잠정값이다. 바꾸면 엔진 버전을 올린다.

점수에 넣지 않는 관찰:

- **시선**: 실시간 안내와 리포트의 관찰 신호. 총점 축이 아니다.
- **간투어**: 체험이 끝난 뒤 Whisper `small`이 저장된 녹음을 다시 받아쓴 추정치. Chrome이 만든 답변 원문은 바꾸지 않는다. 점수에 반영하지 않으며, 분석 불가는 0회가 아니다.

코칭 문장은 관측, 해석, 따라 말할 예시의 순서를 유지한다.

### 5.1 점수 표기

전시 `mvp` 결과 화면은 0~100 점수를 보여 준다. B2B 수강생 화면은 원점수 대신 등급을 쓴다.

| 점수 | 등급 |
| --- | --- |
| 80 이상 | 우수 |
| 65 이상 | 양호 |
| 50 이상 | 보통 |
| 그 미만 | 연습 필요 |

관리·연구 화면은 원점수를 함께 볼 수 있다.

## 6. 결과와 재방문

- 세션 리포트: `GET /api/sessions/{id}/report`
- 4자리 익명 코드 발급: `POST /api/codes`
- 코드로 기록 연결: `POST /api/codes/{code}/claim`
- 최근 기록: `GET /api/history`
- 짧은 설문: `POST /api/sessions/{id}/survey`

개인 식별 정보 없이 코드로 최근 연습 추이를 잇는다.

## 7. API 요약

모든 경로는 `/api` 아래다. 상세 스키마는 서버 `/docs`를 본다.

| 영역 | 주요 경로 | 기능 |
| --- | --- | --- |
| 시나리오 | `GET /scenarios`, `GET /scenarios/{slug}` | 직무 시나리오·에피소드 목록 |
| 세션 | `POST /sessions` | 세션 생성 |
| 세션 | `GET /sessions/{id}` | 이어 하기 |
| 세션 | `POST /sessions/{id}/turns/{turn}/observation` | 비언어 집계 저장 |
| 세션 | `POST /sessions/{id}/turns/{turn}/response` | 답변 제출, 다음 대사 |
| 세션 | `POST /sessions/{id}/turns/{turn}/audio` | 턴 녹음 업로드 |
| 세션 | `POST /sessions/{id}/finish`, `GET .../progress`, `POST .../retry-analysis` | 분석 시작·진행·재시도 |
| 리포트 | `GET /sessions/{id}/report` | 4-Fit 리포트 |
| 음성 | `POST /tts` | 상대 대사 합성. 키·설정이 없으면 브라우저 TTS |
| 코드 | `POST /codes`, `POST /codes/{code}/claim`, `GET /history` | 익명 재방문 |
| 계정 | `POST /auth/signup`, `POST /auth/login`, `GET /auth/me`, `PATCH /auth/me` | B2B 계정 |
| 기관 | `POST /orgs`, `POST /orgs/join`, 멤버·세션 조회 | 초대 코드 기관 |
| NFC | `POST /nfc/issue`, `/revoke`, `/resolve`, `GET /nfc/tap` | 카드 발급·태그 시작. 리더가 없으면 브리지는 쉰다 |
| 운영 | `GET /admin/metrics`, `GET /admin/export.csv`, `POST /admin/reset` | 같은 PC 또는 관리 토큰 |

건강 확인: `GET /api/health`. 대화 준비(`dialogue_ready`)와 서버 STT(`server_stt: "whisper"`)를 따로 본다. `ok: true`만으로 분석 모델이 준비된 것은 아니다.

## 8. 데이터와 개인정보

- 영상 프레임은 브라우저 안에서만 처리하고, 집계 숫자만 전송한다.
- 음성 파일은 저장 동의가 있을 때만 보관한다. 기본 보관 기간은 7일이고, 동의하지 않은 파일은 분석 직후 삭제한다.
- 기본 데이터베이스는 SQLite(`poc/backend/mirror-ting.db`)다.
- 첫 기동 때 테이블을 만들고 시나리오를 시드한다. 같은 시드는 다시 실행해도 중복 삽입하지 않는다.

## 9. 동작 보장과 폴백

| 구간 | 기본 | 실패 시 |
| --- | --- | --- |
| 실시간 받아쓰기 | Chrome STT (인터넷 필요) | 직접 입력. 서버 Whisper로 실시간 대체하지 않음 |
| 간투어 | 서버 Whisper `small` | 미측정. 0회로 바꾸지 않음 |
| 상대 대사 | Gemini 또는 OpenAI | 직장대화 BeatSheet 문장 |
| 상대 음성 | ElevenLabs (서버) | 브라우저 TTS |
| 의미 매칭 | 로컬 E5 | 키워드 판정 |
| 표정·자세 모델 | 로컬 MediaPipe (`npm run setup-offline`) | CDN. 오프라인 전시 전에 로컬 자산을 준비한다 |
| NFC | ACR122U 브리지 | 리더·라이브러리가 없으면 휴면 |

Chrome 음성 인식은 브라우저 제공자의 서버로 음성이 갈 수 있다. Whisper 간투어 분석은 전시 PC에서 처리한다.

## 10. 이 버전에 포함하지 않는 것

- 영상 원본 업로드와 서버측 얼굴 재분석
- 시선 점수를 총점에 더하는 일
- 간투어 횟수를 감점하는 일
- 실시간 서버 전사로 Chrome STT를 대체하는 일
- 가중치 0.35 / 0.30 / 0.175 / 0.175를 최종 확정값으로 발표하는 일

관련 실행 절차는 [프로젝트 가이드](프로젝트-가이드.md), 설치 순서는 [새 팀원 시작 안내](developer-onboarding.md)를 본다.

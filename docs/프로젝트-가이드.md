# Mirror-Ting 프로젝트 가이드

기준일: 2026-09-28

취업 준비생이 AI와 직장 대화를 연습하고 4-Fit 리포트를 받는 전시 프로젝트다. 이 문서는 저장소에서 어디를 고치고 어떻게 실행하는지 정한다. 기능의 동작 정의는 [기능 명세서](기능-명세서.md), 이용 조건은 [라이선스](라이선스.md), 처음 설치 명령은 [새 팀원 시작 안내](developer-onboarding.md)에 있다.

## 저장소 지도

루트에 앱 코드는 없다. 세 갈래로 나뉜다.

| 경로 | 역할 | 손대는 때 |
| --- | --- | --- |
| `mvp/` | 전시 관람객 화면. React, Vite, JSX | 부스에서 보이는 UI, 카메라·마이크, 화면 전환 |
| `poc/backend/` | FastAPI 분석 서버. 대화, 4-Fit, 저장 | 점수, 대사, API, 시드. 분석 로직은 여기만 둔다 |
| `poc/frontend/` | 레거시 웹앱. TypeScript, zustand | 관리·키오스크 계열. 전시 UI 작업의 시작점이 아니다 |
| `docs/` | 기획·운영·안내 | 구현과 어긋날 수 있다. 동작 확인은 코드를 본다 |
| `poc/docs/` | 기술 문서, `prd.json` 스펙 ID | 주석의 `S-` / `F-` / `R-` ID가 가리키는 곳 |

화면은 분석 수치를 다시 계산하지 않는다. `mvp/src/lib/pocApi.js`로 백엔드를 호출한다.

## 로컬 실행

준비된 환경에서 터미널 두 개로 띄운다. Python은 3.12, Node는 20 이상을 쓴다. Windows 전시 PC의 매일 기동은 루트 `start-exhibition.ps1`이다.

백엔드, 저장소의 `poc/backend`:

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Windows:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8001
```

프론트, 저장소의 `mvp`:

```bash
npm run dev
```

Chrome에서 `http://localhost:5173`을 연다. Vite가 `/api`를 `http://127.0.0.1:8001`로 보낸다. 8000 포트는 다른 키오스크가 쓸 수 있으므로 이 서버는 8001을 유지한다. 레거시 웹앱은 5174라서 전시 화면과 동시에 띄울 수 있다.

살아 있는 확인: `http://127.0.0.1:8001/api/health`에서 `dialogue_ready: true`, `server_stt: "whisper"`. 화면만 보려면 `http://localhost:5173/?demo=practice`처럼 데모 쿼리를 쓴다. 데모는 분석 품질을 대신 증명하지 않는다.

## 설정

환경 변수 접두사는 `MIRROR_TING_`다. 기본값은 `poc/backend/app/core/config.py`, 로컬 값은 `poc/backend/.env`다. `.env.example`을 복사해 만들고, 이미 있는 `.env`는 덮어쓰지 않는다.

| 변수 | 의미 |
| --- | --- |
| `MIRROR_TING_DIALOGUE_PROVIDER` | `gemini`(기본) 또는 `openai` |
| `MIRROR_TING_GEMINI_API_KEY` | Gemini 대사 생성 |
| `MIRROR_TING_OPENAI_API_KEY` | 제공자가 openai일 때 GPT-4o |
| `MIRROR_TING_ELEVENLABS_API_KEY` | 상대 음성. 없으면 브라우저 TTS |
| `MIRROR_TING_STT_WHISPER_MODEL` | 간투어용 Whisper. 기본 `./whisper-models/small` |
| `MIRROR_TING_JWT_SECRET` | 계정 기능. 배포 전 기본 문자열을 바꾼다 |
| `MIRROR_TING_ADMIN_TOKEN` | 운영 API. 없으면 같은 PC에서만 `/api/admin` |

키는 서버에만 둔다. 프론트 번들, API 응답, 채팅, 커밋에 넣지 않는다.

## 코드를 둘 곳

- 화면 상태와 전시 동선: `mvp/src/pages/`, `mvp/src/lib/serviceEntryRoute.js`
- 모드·직무·난이도 문구: `mvp/src/data/setupCatalog.js`. 백엔드에는 모드 ID, 난이도, `scenario_slug`만 넘긴다
- REST: `poc/backend/app/api/`
- 세션 상태와 테이블: `poc/backend/app/models/models.py`
- 대사: `poc/backend/app/services/dialogue/`
- 4-Fit 점수: `poc/backend/app/ai/`. 가중치와 엔진 버전은 `scoring.py`
- 시나리오 내용: `poc/backend/app/seed/packs/`

주석과 시드 문장은 한국어로 쓴다. 새 기능에는 `poc/docs/prd.json`의 관련 ID를 주석에 남긴다.

`poc/frontend`만 TypeScript다. 타입 임포트는 `import type`이다. `mvp`는 JSX이며 라우터 없이 화면 상태로 이동한다. 두 프론트의 상태 관리 방식을 섞지 않는다.

## 바꾸면 같이 볼 규칙

- 음성 측정: 녹음이 있으면 실측, 음성 인식 턴은 발화 시간 근사, 텍스트 입력 턴은 Voice-Fit에서 제외한다.
- 간투어 `null`을 0으로 바꾸지 않는다. 점수에도 넣지 않는다.
- 시선은 관찰 신호다. 총점 가중치에 넣지 않는다.
- 점수 산식·가중치·측정 방법이 바뀌면 `ENGINE_VERSION`을 올린다. 다른 버전의 추이를 한 그래프로 합치지 않는다.
- 코칭 문장은 관측, 해석, 따라 말할 예시 순서를 유지한다.
- 자산 폴백은 로컬이 있으면 로컬, 없을 때만 CDN이다. 오프라인 부스 전에 `mvp`에서 `npm run setup-offline`을 실행한다.

## 검증

```bash
cd mvp
npm test
npm run build

cd ../poc/backend
.venv/bin/python -m pytest -q
```

Windows에서 pytest 한글 출력이 깨지면 `PYTHONUTF8=1`을 준다. 레거시 프론트를 고쳤으면 그 디렉터리에서 `npx tsc -b`와 `npm test`를 추가로 돌린다. 린트는 CI에 없으므로 로컬에서 `poc/frontend`의 `npm run lint`를 실행한다.

테스트 통과와 부스 마이크 품질은 별개다. 의미 매칭 임계값과 떨림 기준은 전시 PC에서 다시 맞춘다. 절차는 `poc/docs/demo-checklist.md`다.

백엔드 코드를 고친 뒤 실행 중인 8001 서버에 반영이 필요하면 프로세스를 끝내고 같은 포트로 다시 띄운다. `--reload`가 설정·시드·프로세스 전역 상태를 놓치는 경우가 있다.

## 데이터와 Git

커밋하지 않는 것: `.env`, `mirror-ting.db`, 녹음, 모델 가중치, `.venv`, `node_modules`.

기본 DB는 SQLite다. 스키마를 바꿀 때 운영 DB 파일을 지워서 맞추지 않는다. 시드 스크립트는 비어 있는 테이블을 채우며, 이미 있는 시나리오를 중복 삽입하지 않는다.

작업은 최신 `main`에서 브랜치를 만든다. 자신의 파일만 커밋하고, 다른 변경을 지우거나 강제 푸시로 맞추지 않는다.

## 전시 당일 메모

- 결과 화면을 오래 유지할 촬영은 `?idle=0`.
- 인터넷이 없으면 Chrome 받아쓰기와 클라우드 대사가 멈춘다. 직접 입력, BeatSheet 폴백, 브라우저 TTS로 시연을 이어 갈 수 있는지 미리 확인한다.
- 카메라 분석 오프라인 동작은 MediaPipe 로컬 자산이 있을 때만 된다.
- 운영 초기화(`/api/admin/reset`)는 체험 기록을 지운다. 전시 중에 확인 없이 호출하지 않는다.
